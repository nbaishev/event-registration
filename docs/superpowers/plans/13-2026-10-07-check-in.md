## Contract / Acceptance criteria

- POST `/api/events/{event_id}/check-ins`, JSON `{ticket_code: string}`. Required strict string, без null/coercion. Normalize trim → uppercase → remove spaces и `-`; ровно 12 символов алфавита `23456789ABCDEFGHJKMNPQRSTUVWXYZ`, иначе 422 VALIDATION_ERROR. Удаляются обычные ASCII spaces; прочие внутренние whitespace недопустимы.
- Missing Event → 404 EVENT_NOT_FOUND; wrong owner → 403 EVENT_NOT_OWNER. Body validation выполняет FastAPI; business проверки: existence → ownership → DRAFT/CANCELLED → time → ticket.
- DRAFT → 409 CHECKIN_NOT_OPEN; CANCELLED → 409 EVENT_CANCELLED; now >= ends_at → 409 EVENT_FINISHED; now < starts_at−2h → 409 CHECKIN_NOT_OPEN.
- На нижней границе check-in разрешён, на верхней запрещён. Clock читается после Event lock.
- UPDATE WHERE event_id/code/status CONFIRMED/checked_in_at NULL. При 0 rows повторный lookup scoped к Event и CONFIRMED: checked-in → 409 TICKET_ALREADY_CHECKED_IN, иначе 404 TICKET_NOT_FOUND. Lookup не заменяет conditional UPDATE.
- 200 CheckInResponse точно как spec §35: status checked_in, registration_id, event_id, formatted ticket_code, checked_in_at, participant {user_id,email}. Email берётся из User внутри transaction; commit до возврата; rollback на failure. Существующие timestamps/invariants сохраняются, updated_at обновляется тем же now.
- Parallel same-code → ровно 200 + 409. Cancellation/check-in в обоих lock orders не могут оба успешно завершиться; cancelled ticket после удаления кода не работает.
- Auth cookie, CSRF/Origin и no-store переиспользуются. Wrong-event code → 404 без participant leakage.
- `/organizer/events/:eventId/check-in`: ссылка «Check-in» из details для PUBLISHED; direct route также обрабатывает DRAFT/CANCELLED/errors. Поле «Код билета», pending submit, success email/time/code, сообщения по error.code; не повторять POST автоматически при transport failure.
